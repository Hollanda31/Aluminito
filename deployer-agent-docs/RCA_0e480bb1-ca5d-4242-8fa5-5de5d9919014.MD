# RCA — run 0e480bb1-ca5d-4242-8fa5-5de5d9919014 (aluminito-esquadrias)

## Symptom
Redeploy fails at the **build / pull_source** step during "prepare build context".

## Error (verbatim)
```
prepare build context: read envs: read env file frontend/.env:
open /tmp/agent-env-...-/app/frontend/.env: no such file or directory
```

## Root cause
`pull_source` copies the app from the preview pod `/app` and, while preparing the
build context, reads the standard FARM env files to cache them as the fallback tier
for `write_secrets`. It requires both:
- `backend/.env`
- `frontend/.env`

**`frontend/.env` does not exist in the preview source.** This is not a manifest,
tier, or Secrets-tab problem — it is a missing file in the app source.

## Evidence this is a source regression (files were deleted)
Run history for this deployment:
- `c20e58c3` (initial) — **success** (both .env files present)
- `37e520a9` (redeploy) — **success**
- `6e3cecd6` — failed: `read env file backend/.env ... no such file or directory`
- `daa6acfa` — failed: `read env file backend/.env ... no such file or directory`
- `0e480bb1` (this run) — failed: `read env file frontend/.env ... no such file or directory`

The error moved from `backend/.env` to `frontend/.env`, indicating `backend/.env`
was restored between attempts but `frontend/.env` is still missing. Both files
existed in the two earlier successful runs, so they were removed from the preview
pod `/app` after those deploys.

## Why I did not fix/redeploy
- I have no tool to write files into the preview pod; restoring source files is E1's action.
- The eph sandbox could not load source (`eph_source_access_failed`) because pull_source
  failed before uploading the source archive — so I could not inspect/patch there either.
- Re-running the pipeline unchanged will fail identically at the same step.

## Fix (E1 / Code)
Recreate the missing env file(s) in the app source before redeploying:
- `frontend/.env` — e.g. `REACT_APP_BACKEND_URL=<preview backend url>`
- Verify `backend/.env` exists too — e.g. `MONGO_URL="..."` and `DB_NAME="..."`

These values do not need to be production-correct (production SYSTEM keys —
`REACT_APP_BACKEND_URL`, `MONGO_URL`, `DB_NAME` — are regenerated and overwritten at
deploy time). The files simply must exist for `pull_source` to read. After the files
are restored in `/app/frontend/.env` and `/app/backend/.env`, retrigger the deploy.
